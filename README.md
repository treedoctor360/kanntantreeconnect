# かんたん樹木登録（kanntantreeconnect）

作業中に「この木、番号を振っておきたい」と思った瞬間に、1本を手早く登録するための道具。
紙の **「樹木点検 現地チェックシート」1ページ目** の点検内容も、そのまま入れられる。

[kantantree](https://github.com/treedoctor360/kantantree) と同じ構成に、
**スプレッドシート連携（GAS）** を足したもの。

- アプリを**開くたび**にスプレッドシートの内容を取り込む
- 登録・編集・削除の**たびに自動で**スプレッドシートへ送る（圏外なら溜めて後で送る）

仕様は [CLAUDE.md](./CLAUDE.md)、連携の設置手順は [gas/README.md](./gas/README.md) にまとめてある。

## 公開先

**https://treedoctor360.github.io/kanntantreeconnect/**

`main` に push すると GitHub Actions が自動でビルドして公開する。

### スマホで使い始める

1. 上のURLをスマホのブラウザで開く
2. **ホーム画面に追加する**（毎回URLを開かなくて済む）
   - iPhone (Safari): 共有ボタン → 「ホーム画面に追加」
   - Android (Chrome): 右上の︙ → 「ホーム画面に追加」
3. 最初に **設定タブ → ＋公園を追加** で公園を1つ登録する（これがないと樹木を登録できない）
   - 公園コードは `P001` が自動で入る。そのままでよい
   - その公園にいるなら「📍 現在地を入れる」で代表座標も入れておくと、地図タブがその公園から開く
   - 公園がたくさんあるなら **📤 CSVから取り込む** で一括登録できる（下記）
4. あとは **登録タブ** で「テープ番号 → 樹種 → 点検内容に〇 → 📍現在地 → 📷撮影 → 登録」
5. スプレッドシートに残したいなら **設定タブ → スプレッドシート連携（GAS）** に
   Web AppのURLを入れる（設置手順は [gas/README.md](./gas/README.md)。10分ほど）

初回に位置情報とカメラの許可を聞かれるので許可する。
（`https://` でないとブラウザが位置情報を使わせてくれないため、上のURLから開くこと）

> **写真は端末の中だけに保存される。** スプレッドシートには送らない（容量が大きいため）。
> 機種変更や端末の初期化で写真は消えるので、ときどき
> 設定タブ → **JSON 写真あり** を書き出しておくこと。
> 設定タブに「最終バックアップから◯日」が出る。
>
> GAS連携を設定していない場合は、**公園・樹木も端末の中だけ**になる。

## ターミナル操作

```bash
# 1. 依存を入れる（最初の1回だけ）
npm install

# 2. 開発サーバを起動する
npm run dev
#    → http://localhost:5173/kanntantreeconnect/ が開く

# 3. 採番などのテストを走らせる
npm test

# 4. 本番用にビルドする（dist/ ができる）
npm run build

# 5. ビルドしたものを手元で確認する
npm run preview
```

スマホの実機で試すときは、パソコンと同じWi-Fiにつないで次のように起動する。

```bash
npm run dev -- --host
#    → 表示された http://192.168.x.x:5173/kanntantreeconnect/ をスマホで開く
```

> 位置情報（GPS）と カメラ は、`https://` か `localhost` でないとブラウザが使わせてくれない。
> 実機でGPSまで試したいときは、GitHub Pages に上げたものを開くのが早い。

## 公園をCSVから取り込む

設定タブの **📤 CSVから取り込む**。樹木台帳メモ（parktreenote）の公園マスタと同じ形式なので、
同じCSVを両方のアプリに読ませられる。

| 列 | 扱い |
|---|---|
| `児童遊園地名` / `公園名` / `タイトル` のいずれか | **必須**。公園名として読む |
| `ID` | あれば `pid` として保持（プリザンター等のID） |
| `緯度` / `経度`（`lat` / `lng` も可） | あれば代表座標に入れる |

- 文字コードは UTF-8 でも Shift_JIS でもよい（自動判定）
- 公園コードは `P001` から続きを自動で付ける
- すでに登録済みの公園は飛ばす。表記ゆれ（`皇子が丘公園` と `皇子が丘 公園`）も
  同じ公園とみなす
- 並び順はCSVの行順

## 点検内容（現地チェックシート1ページ目）

紙の **「樹木点検 現地チェックシート」** の各行を、そのまま登録タブで入れられる。
並びも紙と同じにしてあるので、紙と見比べながら進められる。

| 紙の欄 | アプリでの入れ方 |
|---|---|
| 場所 | 公園セレクタで選ぶ |
| 調査日 / 調査者 / テープロール | **調査情報**（折りたたみ）。1枚のシートで共通なので、登録のたびに引き継ぐ |
| テープ番号 | `A201` のように入れると、樹木番号が `公園コード-テープ番号` になる |
| 樹木番号 | 自動で入る。手で書き換えてもよい |
| 樹種（不明可） | 樹種タイル。無ければ「その他（入力）」、分からなければ「不明」 |
| 樹高 | よく使う高さ（3/5/8/10/15/20 m）をタップ。他の値は下の欄へ。**目分量でよい** |
| 葉の茂り | `濃`＝枝先まで密 / `普`＝ふつう / `ま`＝まばら（樹冠から空が透ける）/ `ほ`＝ほとんどない（迷ったら「普」） |
| キノコ | `有` / `無`＝見たが無かった / `未`＝見ていない・見えない（**必ず区別する**） |
| キノコ部位 | `根`＝根元（地際〜50cm・露出根）/ `幹`＝根元より上の生きた幹 / `枝`＝枝の付け根 / `枯`＝枯枝・枯幹 / `不`＝不明 — **複数選べる**。キノコが「有」のときだけ出る |
| 空洞・傷 | `有` / `無`。穴・樹皮の広範囲な剥離・割れ目があれば「有」。大きさの基準はなく、気になったら「有」でよい |
| 空洞・傷の位置 | `根` `幹` `枝` — **複数選べる**。空洞・傷が「有」のときだけ出る |
| フラス | `有` / `無` / `未`。木くずとフンが混ざったうどん状・かりんとう状の排出物（サクラ・ウメ・モモを重点確認） |
| 周辺環境 | 道路・園路 / 電線 / 建物 の有無（`有`／`無`）と備考。**「すべて無」ボタン**でまとめて入る |
| 注意 | 気になった木に印（自由記入） |
| 写真 | 「📷 撮影」で3枚まで |

- **もう一度押すと選択が外れる**（間違えて押しても戻せる）。
- **どれも必須ではない。** 座標と同じで、後から入れてもよい。
- 一覧タブでは、キノコ・空洞/傷・フラスが「有」の木に**赤いバッジ**が付く。
- 紙の注記どおり **1行＝1本**。株立ちも1本として1件で登録する。

### テープ番号の採番

紙の運用ルールどおり、**ロールは使い切るまで場所をまたいで連続して使う**（場所ごとに
区切らない）。そのためアプリも、**公園で区切らず端末全体の最大値＋1**を次の番号として出す。

- テープロール（A・B・C）を選んでいれば、その記号の続き（`A201` → `A202`）
- 記号なしで書いている場合はそのまま数字の続き（`201` → `202`）
- どちらも手で書き換えられる。書き換えたあとは自動では上書きしない
- 登録すると点検内容は消え、テープ番号だけ次の番号に進む。公園・樹種・調査情報は残る

> 紙のルールでは「一度使った番号は二度と使わない（伐採後も使い回さない）」。
> アプリは**登録済みの最大値＋1**を出すので、いちばん大きい番号の記録を削除すると
> その番号を再び提案してしまう。番号を手で確かめてから登録すること。

### 見つけたらすぐ連絡

紙の運用ルール4にあたるものは、入力した直後に画面へ注意書きが出る。

- **フラス「有」** → 全景と近景（形が分かるように）を撮影し、可能なら持ち帰る
- **キノコ「有」＋部位「根」** → 根元の大きなキノコはすぐ連絡
- **空洞・傷「有」＋道路・園路「有」** → 倒れたときの影響が大きいので連絡

## 座標の入れ方

登録タブの座標ブロックは4通り。

1. **📍 現在地を入れる** — その場で取得（誤差の目安も出る）
2. **手入力** — 緯度・経度をそのまま打つ
3. **地図で位置を直す** — 地図をタップ／ピンをドラッグして直す（樹冠の下でGPSがずれたとき）
4. **貼り付け → 読み取り** — 次の形式に対応

| 形式 | 例 |
|---|---|
| Googleマップのリンク | `https://www.google.com/maps?q=35.0116,135.7681` |
| 緯度経度そのまま | `35.0116, 135.7681` |
| 度（日本語の方角つき） | `北35.01394°, 東135.85369°` / `北緯35.01394度 東経135.85369度` |
| 度（英字・度記号） | `N35.01394 E135.85369` / `35.01394°, 135.85369°` |
| 度分秒 | `35°00'41.8"N 135°46'05.2"E` |

方角（北南東西・NSEW）があれば、経度・緯度の順で書かれていても正しく判別する。
短縮リンク（`maps.app.goo.gl/…`）はブラウザから展開できないので、マップで開き直して
アドレスバーのURLを貼り付けること。

**「地図で確認」はGoogleマップ（スマホならアプリ）が開く。** 座標を直したいときは
隣の「地図で位置を直す」を使う。

## スプレッドシート連携（GAS）

設定タブの **スプレッドシート連携（GAS）** にWeb AppのURLを入れると動き出す。
設置手順は [gas/README.md](./gas/README.md)。

```
スマホのアプリ  ──POST（JSON）──▶  GAS Web App  ──▶  スプレッドシート
（GitHub Pages）  ◀──JSON────────
```

| いつ | 何が起きるか |
|---|---|
| アプリを開いたとき | シートの内容を取り込む（他の端末の登録が入ってくる）→ 送信待ちがあれば送る |
| 登録・編集・削除したとき | 2.5秒ほど待ってから、まとめてシートへ送る |
| 圏外だったとき | 端末内に溜める。電波が戻ったとき・次に開いたときに送り直す |
| ヘッダー右上のバッジ | 「同期済 / ◯件待ち / 未送信あり」。**タップで今すぐ同期** |

- 突き合わせは JSON取込と同じ規則。**`id` が一致したら `updatedAt` の新しい方を採用**し、
  知らない `id` は追加する。2台で同じ木を直したら後に直した方が残る。
- 削除は `deletions` シート（削除の記録）で伝える。削除より後に別の端末で更新していた場合は、
  その更新を残して削除を捨てる。
- `trees` シートの列は**紙のチェックシートと同じ並び**（テープ番号 → 樹木番号 → 樹種 →
  樹高 → 葉の茂り → キノコ → キノコ部位 → 空洞・傷 → 空洞・傷の位置 → フラス →
  周辺環境 → 注意 → 写真枚数 → 調査日…）。
- **写真・樹種マスタはシートに送らない。** 写真はBase64がセル上限（5万文字）を超えるため、
  紙の「写真」欄にあたる**枚数だけ**を送る。写真のバックアップは従来どおり **JSON 写真あり**。
- シートのセルを手で直したときは、同じ行の `updatedAt` も現在時刻のISO形式に書き換えること
  （書き換えないとアプリ側の値で上書きされる）。
- Web AppのURL・合言葉（`SYNC_TOKEN`）は**チャットやコミットに載せない**。
  設定はコードではなく端末内（IndexedDB）に保存される。

## データの持ち方

- 保存先は端末内の IndexedDB。GAS連携を設定していれば、公園・樹木はスプレッドシートにも残る
  （写真は端末内だけ）。
- 端末を替えるときは、設定タブの **JSON 写真あり** を書き出して、
  新しい端末で **JSONを読み込む** を実行する。
- 読み込みは「追記マージ」。同じ `id` は更新日時の新しい方を採用し、知らない `id` は追加する。
  実行前に「追加◯件 / 更新◯件」を確認ダイアログで出す。
- バックアップを取らないまま端末を初期化するとデータは戻らない。設定タブに
  「最終バックアップから◯日」を出しているので、ときどき書き出しておくこと。
